# 订单 · 支付流水对账工具

用 Python + SQLite 实现，对订单应收与支付/退款流水做**订单级**核对，而不是一行对一行匹配。支持一个订单多次支付、多次部分退款、退款跨日到账、同号流水冲突、币种/精度差异，并按北京时间结算日生成可版本追溯的对账结果。

页面为单页应用（纯标准库 HTTP 服务 + 原生 JS/CSS，无外部依赖），可筛选异常、展开订单计算明细、查看版本历史、溯源到原始 CSV 行，并导出 CSV。

---

## 快速开始

```bash
# 1) 导入内置样例（day1 + day2）并重算，观察跨日退款带来的版本变化
python3 -m reconcile demo --reset

# 2) 启动页面
python3 -m reconcile serve            # 默认 http://127.0.0.1:8000

# 3) 跑测试
python3 -m unittest tests.test_reconcile -v
```

默认数据库 `data/recon.db`，币种配置 `config.json`。可用 `--db` / `--config` 覆盖：

```bash
python3 -m reconcile --db /tmp/a.db --config config.json serve --port 8080
```

### 命令行

```bash
python3 -m reconcile init
python3 -m reconcile import order   samples/day1/orders.csv
python3 -m reconcile import payment samples/day1/payments.csv
python3 -m reconcile import refund  samples/day1/refunds.csv
python3 -m reconcile recompute
python3 -m reconcile export results -o results.csv
python3 -m reconcile export daily -o daily.csv
python3 -m reconcile export order --order-id S003 -o S003.csv
```

`import` 默认导入后自动重算；加 `--no-recompute` 可只导入。

## 输入文件

| 类型 | 表头 | 说明 |
|---|---|---|
| 订单 | `order_id,receivable,currency` | `receivable` 已扣除售后应退金额；带币种 |
| 支付 | `order_id,txn_id,amount,currency,event_time` | 支付事件，按 `txn_id` 去重/查冲突 |
| 退款 | `origin_txn_id,amount,currency,event_time` | 退款引用**原支付流水号**，同一原支付可有多笔部分退款 |

- CSV 使用 UTF-8（兼容 BOM），金额为十进制字符串。
- 时间按北京时间解释：`2026-11-09 10:00:00` 视为 +08:00；也接受 `2026-11-09T10:00:00+08:00`、`...Z`，统一换算为北京时间。
- 行级错误（空流水号、非法金额等）记入 `import_row_error`，不阻断整批导入。
- 文件按 SHA-256 做**文件级去重**：相同文件重复导入会整体跳过。

## 对账口径

全部金额使用 `decimal.Decimal`，按 `config.json` 的币种小数位量化（四舍五入），**不使用浮点、不自动换汇**。

```
支付总额 = 该订单下、币种与订单一致的支付事件金额合计
有效退款 = 关联到该订单有效支付、币种一致、且不超过剩余支付额的退款
净实收   = 支付总额 - 有效退款
差额     = 净实收 - 订单应收
```

- **结算日**：该订单最早一笔“有效支付”的北京时间日期。没有有效支付时退化为最早支付日期；完全没有支付则显示“未结算”，不进入结算日汇总（仍出现在结果与异常中）。
- **分多次支付**：同一订单的支付事件求和，不做一一匹配。
- **多次部分退款**：按退款事件时间顺序依次占用剩余支付额。超过剩余部分计入 `excess_refund`，作为 `EXCESS_REFUND` 异常单列，且不计入有效退款。
- **币种不一致**：支付/退款币种与订单不一致时，该事件不计入（未换汇），原因 `PAYMENT_CURRENCY_MISMATCH` / `REFUND_CURRENCY_MISMATCH`，订单标记异常。
- **找不到原支付的退款**：进入挂账异常 `ORPHAN_REFUND`，不归属任何订单；原支付所属订单不在订单文件中的退款同样挂账。
- **支付流水对应的订单不存在**：`ORPHAN_PAYMENT` 挂账异常。
- **超额退款**：`EXCESS_REFUND`，差额仍照常计算。

### 去重与冲突

- 支付事件按流水号 `txn_id`：
  - 内容语义相同（订单号、金额数值、币种、北京时间一致；`100.0` 与 `100.00` 视为相同）→ 只算一次，静默去重；
  - 同号但内容不同 → 保留**首次导入**事件参与对账，后续事件写入 `event_conflict` 单独报冲突，订单标记 `TXN_CONFLICT` 异常。
- 退款没有独立流水号，`origin_txn_id` 天然会被多笔部分退款复用，因此退款按**整行语义内容哈希**去重：完全相同的重复退款只算一次；同一原支付下金额/时间不同的退款是合法业务，各自保留，不误报冲突。
- 订单按订单号：内容相同跳过；内容不同（应收/币种变化）保留首次版本，并记入 `order_conflict`，订单标记 `ORDER_CONFLICT` 异常。

### 状态

| 状态 | 含义 |
|---|---|
| `MATCH` | 差额为 0，且无阻断类原因 |
| `MISMATCH` | 差额非 0，无阻断类原因（如少付/多付） |
| `EXCEPTION` | 存在阻断类原因：无有效支付、币种不一致、超额退款、同号/订单冲突 |

`CROSS_DAY_REFUND`（跨日退款）是非阻断提示，不影响 `MATCH`。

## 版本与重复导入

- 订单结果按 `(order_id, version)` 保存；只有 canonical snapshot（结果字段 + 明细 + 原因）变化时才生成新版本，旧版本保留（`current=0`），并在新版本 `change_note` 中自动写出差异原因，例如：
  `状态 MISMATCH → MATCH；净实收 800.00 → 700.00；差额 100.00 → 0.00；新增明细 refund:6（100.00 CNY）；新增原因 跨日退款…`
- 结算日汇总按 `(settlement_date, currency, version)` 版本化。跨日退款会同时更新：
  1. 订单结果（净实收变化）；
  2. 订单原结算日的汇总（按最新订单结果重述）；
  3. 退款发生日的汇总（新建或更新跨日退款调整）。
- **重复导入不会改变已核对一致的结果**：文件级哈希相同直接跳过；即使重算，canonical snapshot 不变则不产生新版本。

结算日汇总的两个金额字段：

- `net_total`：该结算日订单的**最新**净实收合计（退款到账后会重述）；
- `adjustment_total`：退款发生日落在该日、但订单结算日在其他日期的有效退款备忘金额（负值）。

调整金额单独展示、**不并入 net_total**，避免与订单重述重复计算；页面和导出都会明确标注“备忘”。

## 页面功能

- **对账结果**：按结算日、状态、币种、原因筛选，订单号搜索；显示各币种汇总卡片；点击行展开计算公式、逐笔支付/退款/汇总明细、原始行、版本历史与修订原因；可导出当前筛选结果 CSV。
- **结算日汇总**：按日期/币种展示最新版本、订单数/状态计数、应收与净实收合计、跨日退款调整；展开可看调整明细和历次版本。
- **异常与原始记录**：挂账异常、同号流水冲突、订单记录冲突、导入行错误。
- **导入**：上传订单/支付/退款 CSV，导入后自动重算；展示批次与文件哈希。
- 单笔订单明细 CSV 导出、结算日汇总 CSV 导出（均带 UTF-8 BOM，便于 Excel 打开）。

## 设计说明与边界

- 金额在库中以十进制字符串存储，所有加减与比较用 `Decimal`；币种小数位在计算和展示时量化，不做隐式换汇。
- 订单应收被视为最终口径（已扣售后应退），退款用于推导净实收；因此同一订单的历史退款会持续影响其最新结果，这正是版本化的原因。
- 结算日汇总的 `adjustment_total` 是备忘口径，不与重述后的订单净额相加，避免跨日退款被重复计算。
- 退款按“内容哈希”去重而非仅按原支付流水号，是因为部分退款合法地复用同一 `origin_txn_id`；同号冲突检测落在有独立流水号的支付事件上。
- 首次导入版本为权威版本（订单/支付事件）；冲突数据不静默覆盖，而是保留证据并在结果中标记异常。
- SQLite 使用 WAL 与外键约束；整个重算在单个事务内完成，页面每次请求独立连接，适配多线程 HTTP 服务。
